# Plano 03-01: Fluxo de Setups & Tags

**Fase:** 3 — Fluxo de Setups & Tags
**Objetivo:** Fluxo completo: criar/editar/visualizar/excluir/duplicar setups, listagem com filtro por tag, gerenciador de tags, toast.
**Requisitos cobertos:** SET-01,02,03,05,06,07,08; TAG-01..04; LIST-01..04; VIEW-01,02

## Tarefas

1. **`src/components/Toast.tsx`:** `useToast()` + componente fixo `role="status"` com auto-hide.
2. **`src/components/TagInput.tsx`:** chips das tags selecionadas (remover ×) + input com autocomplete de tags existentes (filtra enquanto digita, exclui já selecionadas) + opção `Criar tag "[texto]"` quando não há match exato normalizado; Enter adiciona match ou cria.
3. **`SetupEdit` (rewrite):** modos criar (`/setups/novo`) e editar/visualizar (`/setups/:id`, editável por decisão do projeto); campo nome obrigatório com erro inline; TagInput; Pedalboard carregando valores salvos; ações Salvar (toast + redirect `/setups`), Duplicar e Excluir (confirm) no modo edição; setup não encontrado → mensagem + voltar.
4. **`SetupList`:** cards (nome + chips de tag + data) clicáveis → `/setups/:id`; barra de filtro com chips "Todas" + tags (filtro instantâneo, setups sem tag aparecem em "Todas"); botões "Novo Setup" e "Gerenciar Tags"; exibe toast vindo de `location.state`.
5. **`TagManager`:** lista tags com contagem de setups, renomear inline, excluir (confirm), criar nova; voltar.
6. **CSS:** toast, dropdown de autocomplete, grid de cards, barra de filtro, linhas do gerenciador.
7. **Verificação:** `npm test` + `npm run build` verdes.

## Must-haves (critérios da fase)

- [ ] Criar setup com nome+tags → toast → aparece na listagem sem refresh
- [ ] Sem nome não salva; tag nova oferece "criar tag"; grafia diferente reutiliza
- [ ] Filtro instantâneo; "Todas" inclui setups sem tag
- [ ] Abrir setup mostra pedaleira como salva; editar e ressalvar atualiza
- [ ] Duplicar, excluir (confirm), gerenciar tags (renomear/excluir/contagem)
